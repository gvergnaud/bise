Run a real shell command and return its combined output. Args: the command (`arg`) and a `description`. {edit_line} The command may span multiple lines (if/for blocks run as written). Search files and file contents with `rg` (ripgrep) when it is installed (faster, output easier to scan), else with `grep -rn`: the system prompt says whether this machine has `rg`. Notes: a process writing more than ~50MB to any file is terminated (exit 153); a command's stdin is /dev/null (a command that reads stdin gets EOF at once); a command that needs input later must read it from the fifo named by `$BEND_STDIN` (e.g. `python3 -i < "$BEND_STDIN"`), then waits for input until fed or killed; temp scripts are deleted after each call.

A command that runs longer than the sync window (30 seconds) is not killed: it keeps running as a BACKGROUND process and the tool returns immediately with a file contract: every line is a ready-to-run command on concrete paths, with the process real pid already substituted (copy-paste verbatim). Interact with it using further bash calls: read new output with `tail -n 50 <dir>/<id>.out`, feed stdin with `printf '%s\n' 'text' > <dir>/<id>.in` (only if the command was started reading `$BEND_STDIN`), check liveness with `kill -0 $(cat <dir>/<id>.pid)`, get its exit code with `cat <dir>/<id>.rc`, list all background commands with `ls <dir>`, and kill one with `kill $(cat <dir>/<id>.pid)`. Decide yourself whether a long-running command is still worth its slot, and clean up when done.

Always set `description`: one short line shown to the user while this runs (the code itself is hidden from them by default): what you are doing, in the user's language. 8 words at most, starting lowercase, no final period. E.g. 'weighing the hero image', 'je lance les tests du signup'.
