timers: what wakes your agents, and when

you: "they're scheduled tasks, really? they should show as something new in the interface" and "Codex has it: you can list them, act on them, stop them."

today a timer is a message from "switchboard" with a long instruction and a (stop it: sb every --stop 48) tail, and its start and end leave nothing. the proposal: a timer is its own thing, with its glyph ◷, quiet lines in the thread, a mark on the agent's row, and /timers to list, open, run and stop them.

the word and the glyph

timer, not "scheduled task": in bise's screens a task is called an agent, and "scheduled task" would read as a new agent that runs on a schedule. a timer is simpler and true: it wakes an agent you already have, in its own thread, with the words it was set with. it's also the word agents use (sb every).

◷ (a clock face, one cell wide): ⏱ is an emoji in most fonts and takes two cells. ◷ needs its line in glyph-audit.md like every glyph, with an ASCII form for the terminals that lack it (my pick: @, "at a time").

like Codex, and not: Codex's app lists its Scheduled tasks in the sidebar with active / paused / completed, run now and edit. all of bise's timers wake an agent in its own thread, so i take the list, the next run, run now and stop; i leave pause and custom schedules for later.

in the thread

one faint ◷ line each, like the hub's other lines, the words folded behind ▸: set, each wake (with "waited 4m" when its agent was busy), ended (ran its 6 times · stopped by you · stopped by answer-line · its end time passed · answer-line is gone). no "switchboard", no (stop it: …): /timers and x do that. in main's thread: the timers main sets and how they end, never another agent's wakes. the agents panel marks an agent with a timer: ◷ and its next wake, in place of the time.

/timers: every timer, every agent

a full screen like /artifacts: the running ones, soonest first; tab shows the ended ones too (the last 7 days, dim). / finds by agent or words. a timer that keeps a page fresh shows the page as a ↗ chip: stopping it ends the page's "watching" too.

one timer, opened

⏎ on a row: who it wakes and who set it, how often, the next wake with its countdown, how many so far, when it ends, the words in full, and its last wakes with what happened.

stop

x asks on the row itself, like archiving an agent does: y stops, n or esc keeps. stopped, the row leaves the running list (tab still shows it, ended), and the agent's thread gets ◷ timer #48 ended · stopped by you. run now (r) asks nothing: it's one wake, the same as the timer's own.

v1

  • in: the ◷ lines in the thread (set, wake, waited, ended) · the ◷ mark with the next wake on the agent's row · /timers (running, tab ended, / find, ⏎ open) · x stop with y / n · r run now (one hub op: sb every --run 48).
  • later: change how often (tell the agent instead: "@answer-line every 5m instead") · pause · a timer you set yourself from /timers.
  • words: timer · ◷ · /timers "what wakes your agents, and when" · "next 14:32 · in 1m" · "2 of 6" · "until 18:00" · "once" · "every day 07:30" · ended: "ran its 6 times" / "stopped by you" / "stopped by answer-line" / "its end time passed" / "answer-line is gone" · "waited 4m for answer-line to finish" · stop: "stop answer-line's timer? it won't wake answer-line again. y stop n or esc keep" · run now: "ran now: answer-line is on it. the next wake stays at 14:32."
