what counts, and how it gets in

the same afternoon in every mock: you asked for a less busy pricing page. pricing-page made a bise page (v3) and a sheet with the numbers; earlier, launch made an onboarding deck, ambient a local site, pr-review a PR, and subs-lead, archived since tuesday, a design doc.

three ways in, never from file writes alone. 1. the agent says so: sb artifact add <path or link> --title "pricing page"; its prompt says: add what you made for the user to look at, not the code you changed for a task (that's the commit), not scratch files. 2. by itself where it is certain: every bise page, with its versions and notes. 3. you add it: /artifacts add <path or link>.

why not from every write: an agent writes dozens of files a turn (tests, scratch, builds). the list would drown in a day and you'd stop trusting it. the same path or link again is a new version of the same artifact, never a second row.

A · an "artifacts" tab in the agents panel always in view

the panel's title gets a second word: agents · artifacts · 14. a click on it, or ⌥ + m, switches. two rows per artifact: the title, then kind · agent · age. a click opens it. the catch: 30 columns cut the titles, the panel stops being the agents' place, and under 90 columns there is no panel at all, so A needs B's screen anyway.

B · /artifacts, full screen my pick

like /log or a full-screen card: one list, newest first, grouped by day, the same at 80 and 150 (columns drop as it narrows). you type to find; tab switches between every agent and the one in view. the line under the list says what the selected one is and where it lives.

B · the key states

search: type and the list narrows; the letters that match are in the accent. versions: v opens them under the row; a bise page has its own, and a file gets one each time it's added again (bise keeps a copy). quick look: space opens macOS's preview over the terminal, ↑↓ previews the next one, space closes it. an archived agent's artifact: it stays in the list; when its folder is gone, ⏎ opens the copy bise kept.

C · no new place: lines in the thread, and @ B's doors

each time an agent makes one, a ↗ line in the thread: a click opens it, forever (↗ already means "opens outside the terminal"). @ finds artifacts by name, next to agents and files; picking one puts a ↗ onboarding deck chip in your message (never @name, which sends to an agent), so main knows which one you mean. alone, C leaves "the deck from tuesday" to scrolling or memory, which is the problem you asked to solve. with B, these are its doors.

D · diffs, in a panel on the right new: your ask

an agent's changes, or any branch, against main, drawn in the TUI. like Codex's review pane: it opens on the right only when you ask, takes the agents panel's place, and closes back to it. at 80 columns there is no right side, so it takes the screen, like /artifacts.

the doors: a click on ± 3 files under an agent's "landed" or working line · a click on a branch in the agents panel (the ψ of an agent in its own worktree, a shared worktree's label like ψ sculpt) · ctrl+g for the agent in view · /diff picks any branch, PRs and branches without an agent too.

what it shows: the branch vs main, commits and changes not committed yet together, live while the agent works. a header with the files and the +/− counts, then each file with its hunks, old and new line numbers, added lines tinted green, removed ones red. many files: the first 6 on top, f opens the whole list with a filter. big ones fold: a file over 200 changed lines shows its first hunks and ▸ 212 more lines · ⏎ shows them; lock files and generated files fold by themselves; an image is one row that opens it. ⏎ on a line opens the file there in your editor, the same editor as file links today.

keys ↑↓ or the wheel scroll · ] [ next and previous file · f the file list · ⏎ open the line in your editor, or unfold · esc gives the keys back to the composer · ctrl+g closes. one view only, unified: at 150 the panel is 80 wide, too narrow for side by side.

and the artifacts: a landed change is not an artifact (it's in git, and the list would fill with commits), but a PR is, and ⏎ on a PR in /artifacts opens this diff, with o for GitHub. from Codex, from memory: its app shows a review pane on the right with the changed files and their diffs; its CLI has /diff, the git diff in the transcript.

E · artifacts named in a reply new: your ask

when an agent says "i finished the mock", the mock's name is a chip: ↗, its title, the chips' tint and the accent. a click opens it, the same as ⏎ in /artifacts. it looks like nothing else in the thread: a link is underlined text, a file is underlined text, an artifact is a chip.

how an agent writes it: two ways, both turned into the chip by the TUI. 1. a markdown link to the artifact, [the artifacts mock](artifact:artifacts), or to a version, artifact:artifacts@v3; sb artifact add prints the id. 2. nothing new to learn: a plain link or path in a reply that is a registered artifact (bise.dev/m/artifacts, docs/plans/q3.xlsx) shows as its chip with its title. the prompt says: when you name something you made, link it.

the rest: hover shows what it is in the key bar (kind, version, who, when, where). a chip never wraps across two rows. a gone file's chip is struck through, ▲ after it, and still opens the copy. copied as text, a chip gives "artifacts mock (bise.dev/m/artifacts)". the pick: B, with C's doors

  • one home: /artifacts. room for titles, versions and keys, the same at 80 and 150.
  • doors: the ↗ line in the thread when one is made · @ finds them by name · ↗ 3 new in the header since you last looked, a click opens the list.
  • the panel stays the agents' (no A): it's full on a busy day, and gone under 90 columns.
  • archived agents keep their artifacts, with "· archived" after the name. opening one never needs a restore.
  • files that go away (an agent's temp folder when it's dropped, a worktree when it's archived): bise keeps a copy of each version when it's added, 50 MB at most per file.
  • mouse: a click opens, the wheel scrolls, a click on v3 opens the versions.
  • in replies (E): an artifact an agent names is a ↗ chip that opens it.
  • diffs (D): the right panel on demand at 150, full screen at 80; never opened by itself, the "± 3 files" link waits for your click.
  • later, ambient: the hub keeps the list (an artifact event, pages being one kind), so ambient's "for you" home becomes this list and fn + o opens its first row. nothing to design there now.
