## Why

The same UI word was written three times: in the TUI (Rust), in the
desktop (TS) and in the tests (literals). 84 tmux tests hard-coded the
words they wait for; 7 fixtures (anchor_label, composer_parts,
wait_words, via_fn, …) existed only to pin a Rust copy and a TS copy of
the same words. A word change broke tests again and again: c0e36825
('type to ask'), bb660b1e3 (tui_cards_tmux), 8bbbd2380 (ambient-qa rows),
fa548fa11 (5 desktop checks "follow the words").

## The shape

- `rust/proto/src/words/<area>.rs`: one `words!` block per area (common,
  composer, inbox, panel, scheduled, settings, thread). A word with no arg
  is a `&str` const, a template `{arg}` a fn with its args by name, a
  plural `one "…" | "…"` picks on `n`. The rules are in `words/mod.rs`'s
  header: designer owns the words, UI words only (never what an agent
  reads), logic that is not data stays a Rust fn, `common` only for a word
  two areas read, every key read by a client (`tests/words_read_check.py`).
- Generated by `rust/proto/tests/ts.rs` (one bless, fresh-checked by
  proto_ts): `apps/desktop/src/proto/words_<area>.gen.ts` (+ `words.gen.ts`)
  and `tests/words/<area>.gen.json`, per area so the area chunks never
  share a file.
- `tests/words.py`: `w("inbox.where_thread", agent="main")`, `w_re(key)`.
- `tests/word_lint.py` + `tests/word_literals.txt`: a test literal that is
  a catalog word is red past its file's count; the list only shrinks
  (a change that adds keys may count their old literals in other areas'
  tests, for that area's chunk). gate.sh quick on the changed files (all
  of them when the catalog changed), gate.sh full `--all`.

## The chunks

0. The catalog, the generators, words.py, the lint; seed: the inbox
   history's words (`inbox::words`), and tui_inbox_tmux on keys.
1. One chunk per area, in parallel: each moves its area's words into its
   `words/<area>.rs`, deletes the TS copies and the twin fixtures that only
   held words (a fixture that pins logic stays, with its TS twin), moves
   its tests onto keys and lowers word_literals.txt. Words never change in
   a move; tui-parity screens and desktop shots stay byte-identical.

Done when every area is moved, a word changed in the catalog alone moves
the TUI, the desktop and every test with no test edit (full gate green on
a throwaway branch), and word_literals.txt is empty or each line left
names its owner.

## Follow-up: a nightly word mutation (architect m_27743)

The end proof (one word changed in the catalog only) found 4 unit tests
that hard-coded the word: the ratchet reads tests/*_tmux.py and
apps/desktop/tests/** only. It stays so: in a Rust or vitest unit test a
literal is often the expected output of formatting logic (clip, fit,
plural), which a lint can't tell from a word that should be a key.

Instead, make the proof repeatable: a nightly step that, in a scratch
tree, rewrites every catalog text (a marker added to each, its holes
kept), regenerates (BISE_PROTO_BLESS=1), and runs the Rust and vitest unit
tests and the files word_lint reads. A test red there hard-codes a word:
the report names it, and its fix builds the expected value from the key
and its args. Owner: words-lead, or whoever main gives it.
